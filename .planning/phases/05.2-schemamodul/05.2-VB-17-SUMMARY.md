# Samlad förberedelse av valbara block

Den nya `ProtectedElectivePreparation` använder det gemensamma kontraktet från VB15 och API:t från VB16. Normalflödet förbereder flera valramar och båda separata kursvalen tillsammans. Godkänd timplan, poäng och terminsminuter är källor, inte nya uppgifter som användaren behöver kopiera mellan formulär. Flödet kan sparas på timplansnivå före klasskoppling. Faktisk materialisering kräver riktiga aktuella klasser.

## Levererade filer och gräns

- `web/app/protected-elective-preparation.tsx`: samma skyddade komponent för godkänd timplan, valbara block och tjänstefördelning.
- `web/app/elective-preparation.css`: en arbetsyta med avdelare, detaljer vid behov, fasta åtgärder och telefonanpassning. Inkluderar launcherns `.elective-preparation-entry` och `.elective-preparation-entry-actions`.
- `web/app/elective-catalog-picker.tsx`: export av den faktiskt inlästa katalogidentiteten och neutral tomtext även före klasskoppling. Befintlig sökning och GR-språkalternativ återanvänds.
- `web/e2e/elective-preparation.spec.ts`, tre syntetiska fixtures och testmatchning i `web/playwright.elective.config.ts`.

Root äger launcher, home/timplans-/tjänsteinkoppling, journalhelper, handbok, gemensam regression, riktig databasprovning och installation. Inga ändringar gjordes här i STATE/ROADMAP eller annan agents implementation. Inga egna commits gjordes före rootens integration enligt samordningsbeslutet.

## Props och API

```ts
{
  scope: {unitId, planId, schoolYear, columnId},
  identityKey: string,
  contextEpoch: number | null,
  onSessionLost: () => void,
  onClose: () => void,
  onApplied?: (blockIds: string[]) => void,
  initialRows?: string[],
  onOpenBlocks?: (context: {unitId, schoolYear}) => void,
  onOpenTimplan?: (scope: ElectivePreparationScope) => void
}
```

`onApplied` körs när användaren väljer **Bemanna grupper** efter bekräftad tillämpning eller ett skrivfritt återbesök. Callbacken körs inte automatiskt av nätverkssvaret. Rootlaunchern kopplar detta till en direkt övergång och uppdatering av den äldre blocklistan. `onOpenBlocks` öppnar Valbara med exakt källskola/läsår; `onOpenTimplan` öppnar rätt skolas/läsårs timplanslista. Den senare åtgärden heter därför **Öppna timplaner för skolan**. Inga ospecificerade nyflikslänkar används. Callbacknavigering bekräftar eventuell osparad inmatning endast genom rootens navigationsskydd.

POST `/api/valbara-block/forberedelse/lasa` läser fryst källa och eventuell förberedelse. `/kommando` tar ett typat `save` eller `apply`; hela granskade paketet skickas i ett enda kommando. `/status` återhämtar endast en minimal ägd referens. Reply måste stämma med scope, commandId, action, payloadHash, revisionskedja och begärt utkast. Vid återhämtning efter omladdning rekonstrueras payloadhashen med `assertElectivePreparationReplyHash` från det oföränderliga kvittot. Status är inte en ursäkt att skapa ett nytt kommando.

Journalnyckel kommer från rootens `preparationJournalKey`. SessionStorage innehåller endast scope, commandId, action och payloadHash. Inga elevuppgifter, alternativa namn, utkast eller hela kommandon lagras där. Smuts- och navigationsregistrering använder prefixen `elective-preparation:` respektive `navigation-block:elective-preparation:`. Läsning följer stabila scopeprimitiver; ändrad objektidentitet i launcherns scope orsakar ingen omläsningsloop.

## Användarbeteende

Användaren markerar valramar, väljer riktiga klasser om de finns, väljer ett giltigt tidsupplägg och söker konkreta alternativ. 200-poängsfallet kan föreslås som ett höstval och ett vårval på 100 poäng vardera. Alternativet **Två lika stora kursval – dela tiden lika** delar verkliga terminsminuter mellan två kursval utan att omvandla poäng till timmar. Normalflödet visar ärvd tid i stället för åtta råa terminsfält. **Annan fördelning** är ett uttryckligt gymnasieval med totalsummor som kontrolleras mot timplanen. Grundskolan använder ett val med null-poäng och erbjuder ingen omöjlig custom-profil.

Sökningen begränsas av respektive positions tillåtna poängomfattning och konkreta koder. GY-källans `catalogId` jämförs med den faktiskt inlästa Skolverketskatalogens sha256-identitet, enligt verifierad backendsemantik. Annan katalogversion kan inte användas tyst. Saknad GR-källa visas som ett underlagshinder med åtgärd, inte som krav på gymnasiepoäng eller påhittade årskurs-/grupprader.

Gruppnamn, parallellgrupper, klassurval och uppskattat elevantal kan justeras i separata detaljer. Profilbyte bevarar stabila befintliga positions-/block-/alternativ-/grupp-ID:n och egna namn. Automatiska höst-/vårnamn kan följa det nya upplägget. Byte från två till ett val använder exakt en identitet; utbud som inte längre passar måste rättas uttryckligt. Återanvändning av utbud skapar egna alternativ-/grupp-ID:n i det andra kursvalet, lägger till saknade alternativ och raderar inte redan valda alternativ eller skapar ämnes-/språkdubbletter.

Granskningen visar valda klasser, blocknamn, tid, konkreta alternativ, gruppnamn, gruppernas klasser och uppskattat elevantal. Elevtid skiljs från gruppundervisning: två kursval på sammanlagt 180 elevtimmar kan exempelvis kräva 270 grupptimmar med en extra parallellgrupp. Elevval, medlemskap, VH-policy och publicering öppnas inte av detta kommando.

**Efter apply är förberedelsen skrivfri.** Färdigvyn visar befintliga block och länkar till bemanning, tillbaka och **Visa sparad förberedelse**. Den sparade förberedelsen visas utan formulär, Spara/Uppdatera/Skapa eller redigeringsknappar. Ändringar hänvisas till de befintliga blocken. Även kommandofunktionen spärrar skrivning om någon appliedRevision finns. Pending status kan fortfarande kontrolleras i det skrivfria läget. Detta följer SQL:s avsiktliga skydd av materialiserade grupper, bemanning och elevval.

Vid källkonflikt kan aktuellt underlag hämtas med lokal inmatning kvar. Nyare sparad förberedelse får inte överskrivas med ett gammalt utkast. Ändrade detaljrevisioner behöver explicit rättas. Befintliga manuella block visas konkret och stoppar ny materialisering ovanpå dem. En vald ram med redan sparad tidsfördelning (`detailRevision>0`) och ingen appliedRevision kan sparas som förberedelse men får inte granskas/tillämpas över de befintliga kurspositionerna. Den konkreta versionen och ärvda tiden visas med **Fortsätt i Valbara block**. Root/backend har samma ramomfattande skydd; ingen tyst adoption av tidigare tidspositioner görs. Osäkert utfall, fel kvitto, skadad journal och efterföljande läsfel spärrar ytterligare skrivning. MFA visas vid åtgärderna. Förlorad behörighet tömmer den skyddade arbetsytan. Fel knyts till relevanta kontroller och öppnar dolda gruppdetaljer vid fokus.

## SS12000 och kvarstående integration

SS12000:2024/OpenAPI2.1.0 enligt VB14. Förberedelsen är intern planeringsinformation. Samma stabila verksamhetsidentifierare används genom förslag, serverutkast och explicit tillämpning. Riktiga klasskopplingar krävs för materialisering. Inga person-, elev-, medlemskaps-, lärartjänst- eller publiceringsdata ändras av UI-förberedelsen. Ingen extern standardexport eller verklig anslutning verifieras genom komponentproven.

Root behöver slutföra faktisk timplan→förberedelse→gruppunderlag→bemanning/elevval-kedja, handbok och installation. Den nya UI-katalogspärren får inte beskrivas som ett stöd för godtyckliga historiska kataloger. Saknad verifierad historisk GR-årskurskarta är fortfarande ett underlagshinder. Root har kopplat callbackroutning till befintliga block respektive skolans timplanslista med exakt skola/läsår och rätt skolform. Läsningen innehåller inte det offeringId som krävs för att öppna en bestämd timplan direkt, så åtgärden påstår bara att den öppnar skolans lista. Komponenten skapar inget nytt timplansunderlag.
