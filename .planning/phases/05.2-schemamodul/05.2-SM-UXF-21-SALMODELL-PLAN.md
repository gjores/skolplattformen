# UXF-21: Salregister och salbehov

**Mål:** Salar har stabilt ID, platser och utrustning. Varje undervisning har ett salbehov: Lämplig allmän sal, Särskilda salskrav, Sal behövs inte, eller obesvarat. Antaganden A4–A8, A12.

**Gör:**
1. Valfria villkorsfält `salregister` (`id` `sal-N`, namn, platser eller okänt, utrustning, allmän sal ja/nej) och `salbehov` (undervisningens referens, läge, krävd utrustning, tillåtna salar, önskad sal, undervisningsform). Tolkning och rimlighetskontroll i kontraktet; grunden omfattar båda.
2. `lampligaSalar`: snittet av alla krav. Varje sal får skäl när den faller bort (för få platser, saknar utrustning, inte allmän, inte vald). Okänt elevantal eller okända platser ger "kapacitet inte kontrollerad".
3. Underlaget: med register blir motorns sal-ID registrets ID (inte listans ordning). Passets tillåtna salar kommer från salbehovet; äldre salvillkor gäller när salbehov saknas. Tom mängd ger hindret `sal_saknas` med undervisningens namn, och passet får ingen sal.
4. `overforSalnamn` (uttrycklig överföring, namn n → `sal-n`), namnbyte som följer med i villkor och aktiviteter, borttagning som redovisar berörda behov.
5. Rust: prov att motorn löser och kontrollerar med glesa sal-ID (`sal-2`, `sal-7`).

**Blir sant:** en borttagen sal flyttar inte andra pass till fel sal. Två krav ger färre salar än ett. Ett utkast utan register räknas exakt som förut (oförändrat fingeravtryck).

**Kontroller:** `node --test lib/schema-salregister.test.mjs lib/schema-underlag.test.mjs lib/schema-draft.test.mjs`; `cargo test --release -p` berörd crate.

**SS 12000:** `Room` (`id`, `displayName`, `seats`). Här: `sal-N` är internt ID, namn → `displayName`, platser → `seats`. Utrustning, allmän sal och salbehov finns inte i standarden. `Room.id` som UUID och `owner` saknas tills registret får egen tabell (A4); inget utbyte prövas.
