# 05.2-SM-FLYTT: Flytta pass för hand med synliga regelavvikelser

**Status:** skiva 1 genomförd 2026-11-12 på användarens uppdrag "Ja, bygg skiva 1" (se `05.2-SM-FLYTT-SUMMARY.md`; inte installerad). Skiva 2 är inte planerad. Bygger på användarens besked samma dag: "redigera och bryta" betyder att flytta pass för hand och få se vilka regler flytten bryter, inte undantag från ramarna per klass eller dag. Berör SCHEMA-03 och SCHEMA-08 delvis.

## Mål

Den som tagit fram ett schemaförslag kan flytta ett pass till en annan dag och tid. Flytten genomförs även när den bryter en regel, och varje brott visas i klartext vid passet och i en samlad lista. Ingenting luckras upp tyst.

## Val (förval, kan ändras)

| Nr | Val | Skäl |
|---|---|---|
| F1 | Reglerna prövas bara av schemamotorns kontrollant, genom ett nytt anrop `POST /v1/validate` (underlag + placeringar → regelbrott med berörda pass och resurser). Appen räknar inga regler själv. | En källa för reglerna; kontrollanten finns redan (`schemamotor/crates/validate`) |
| F2 | Skiva 1 lagrar inget. Appens rutt bygger om underlaget ur samma läsningar och jämför med det fingeravtryck som förslaget bar. Har underlaget ändrats avvisas flytten med beskedet att ett nytt förslag behöver tas fram. | Prövar arbetssättet utan migration; en ändrad tjänstefördelning kan inte ge fel pass |
| F3 | En flytt som bryter en regel tillåts och märks: passet får en avvikelsemarkering, listan "Regelavvikelser" visar text med namn. Brotten räknas om för hela schemat efter varje flytt, så att ett brott som försvinner också försvinner i vyn. | Användarens besked: bryta ska gå, men synas |
| F4 | Flytt görs med tangentbord och pekare: välj pass → välj dag och starttid (motorns startrutnät, 10 min, inom skoldagen). Dra-och-släpp är ett tillägg, inte enda vägen. | Tillgänglighet; telefon |
| F5 | Skiva 2 (egen plan, kräver migration): sparat schemautkast med underlagets ögonblicksbild, handflyttade pass som låsta, "räkna om resten", och skoldagens ramar som skolan ställer in. Installation på 3012 kräver användarens ja. | Flyttar som ska finnas kvar måste lagras |

## Leverans skiva 1

1. `schemamotor/crates/service`: `POST /v1/validate` med samma token-, storleks- och samtidighetsgränser som `/v1/solve`. Prov i Rust.
2. `web/lib/schema-contract.ts`, `schema-underlag.ts`: fingeravtryck i förslaget, strikt tolkning av kontrollsvaret, namnsatta regelbrott. Nodtester.
3. `web/app/api/schema/kontroll/route.ts`: skyddad rutt (samma behörighet och MFA som förslaget).
4. `web/app/schema-workspace.tsx`: flytt, avvikelsemarkering, lista, ångra senaste flytt, besked om att flyttarna inte sparas.

## SS 12000

Version 2.1 är avsedd referens. Ett lagt pass motsvarar `CalendarEvent`; i skiva 1 lagras och utbyts inget. Regelbrott har ingen motsvarighet i standarden (utanför omfattningen). Inget är verifierat mot standarden.

## Designsystem

Skolplattan: befintliga `.status-badge` och varningsfärger för avvikelser, shadcn `Button`/`Select`. Nya mönster: valt pass, avvikelsemarkering (röd kant och texten "Regelavvikelse") och flyttpanel som följer skärmens nederkant – förs in i designsystemet med rutnätet när vyn godkänts.

## Kontroller

- `cargo test --release`; nodtester; `tsc`, `oxlint`, `npm run build`.
- Kedjeprov: flytta ett pass till en tid där samma elever redan har pass → kontrollanten ger just det brottet; flytta tillbaka → 0 brott; ändrat underlag → avvisas.
- Vyn på dator och telefon, med tangentbord.

## Återstår efter skiva 1

Lagring och låsning (F5), omräkning runt låsta pass, skoldagens ramar per skola, handbokssida när något är installerat.
