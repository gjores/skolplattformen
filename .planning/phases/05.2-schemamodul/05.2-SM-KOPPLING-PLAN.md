# 05.2-SM-KOPPLING: Schemamotorn kopplad till appen (första skiva)

**Status:** genomförd 2026-11-12 (se `05.2-SM-KOPPLING-SUMMARY.md`; installerad lokalt på 3012, se `05.2-SM-INSTALL-2026-11-12.md`) på användarens uppdrag "Koppla till appen". Berör SCHEMA-01, -03, -04 delvis; inget krav blir klart av planen.

## Mål

Rektor eller skoladministratör väljer skola och läsår, trycker **Ta fram schemaförslag** och får ett veckoschema räknat av Rust-motorn ur skolans tjänstefördelning. Förslaget visas, sparas inte och publiceras inte.

## Val (förval, kan ändras)

K4 (antal veckor) och K5 (block som gemensamt pass) är ersatta av `05.2-SM-ELEVER-KALENDER-PLAN.md` (E2–E4) 2026-11-12.

| Nr | Val | Skäl |
|---|---|---|
| K1 | Motorn körs som egen tjänst (`schemamotor-tjanst`, HTTP på 127.0.0.1). Appens server anropar den; webbläsaren når den aldrig. | SCHEMA-04, användarbeslut 2026-10-19 |
| K2 | Underlaget byggs på servern ur `tjanst_plan_read` med befintlig behörighet (rektor, skoladministratör) och befintlig granskningshändelse. Ingen ny tabell, ingen migration. | Inget att installera i databasen; schemaläggaruppdrag (SCHEMA-02) finns inte än |
| K3 | Motorn får bara löpnummer (`larare-1`, `grupp-1`, `kluster-1`, `behov-1`, `pass-1`), tider och kopplingar. Namn och appens ID stannar i appen och sätts på svaret där. | Minsta möjliga uppgifter utanför appen |
| K4 | Veckotid = terminens behov delat med antal undervisningsveckor (anges i vyn, förval HT 18, VT 20). Veckotiden delas i lika pass om högst 80 min, avrundat till 5 min. Under 20 min i veckan läggs inte. | Lektionsindelning finns inte i appen än |
| K5 | Valbart block: alternativen läggs som ett gemensamt pass för blockets klasser och alla blockets lärare. Undervisningsgrupp över flera klasser upptar hela klasserna. | Elevernas val per grupp läses inte i denna skiva; hellre för strängt än dubbelbokat |
| K6 | Flera lärare på samma behov: "samtidigt" → alla på varje pass; annars fördelas passen efter lärarnas tid. Samläsning → ett pass för radernas klasser och samläsningens lärare. Vakant eller ofördelat behov → pass utan lärare. | Följer tjänstefördelningens modell |
| K7 | Skoldag 08:00–16:30 måndag–fredag, 10 min rast, lunch 40 min mellan 10:30 och 13:30, 10 s räknetid. Klasstorlek antas vara 25 (påverkar inget utan salar). Fasta förval. | Skolans ramtider lagras inte än |
| K8 | Anropet är synkront med tidsgräns. Kö, jobbstatus och avbryt i appen återstår (SM-06). | Minsta fungerande koppling |

## Leverans

1. `schemamotor/crates/service`: `GET /v1/health`, `POST /v1/solve` med bärartoken, storleks-, tids- och samtidighetsgräns. Prov i Rust.
2. `web/lib/schema-contract.ts`, `web/lib/schema-underlag.ts`: kontraktstyper, strikt tolkning av motorns svar, underlag ur tjänstefördelningen, namnsatt förslag. Nodtester.
3. `web/lib/server/schemamotor.ts`, `web/app/api/schema/forslag/route.ts`: skyddad rutt; motorn anropas efter att databastransaktionen är klar.
4. `web/app/schema-workspace.tsx` + navigering "Schema" för rektor och skoladministratör.

## SS 12000

Version 2.1 är avsedd referens. Ingen ny lagrad information och inget informationsutbyte. Underlagets källor behåller sin mappning (lärare ← `Duty`, klass/grupp ← `Group`, behov ← `Activity`); ett lagt pass motsvarar `CalendarEvent` men lagras inte. Löpnumren mot motorn är inte externa ID:n. Sal (`Room`) saknas i appen. Inget är verifierat mot standarden.

## Designsystem

Skolplattan: `.page-heading`, `.empty-state`, `.status-badge`, shadcn `Button`, befintliga färg- och radievariabler. Nytt mönster: veckorutnät för schema (`schema.css`, bara befintliga variabler) – ska föras in i designsystemet när vyn godkänts.

## Kontroller

- `cargo test --release` i `schemamotor/`.
- `node --test lib/schema-*.test.mjs`, `npx tsc --noEmit`, `npx oxlint app lib`, `npm run build` i `web/`.
- Hela kedjan: `node ../work/schema/verify-koppling.mjs` från `web/` – underlag ur en syntetisk tjänstefördelning → tjänsten (nekar utan token) → tolkat svar, och motorns kontrollant ger 0 brott.
- Vyn på dator och telefon: `npx playwright test -c playwright.schema.config.ts` i `web/` (fixtur med simulerat API och ett riktigt motorsvar på syntetiska data).
